# RabbitMQ headers binding editor audit

This is cycle 1 of the two additional audits requested after the completed PR61/PR62 batch and verified release v1.5.20. The baseline is current `main` at `5e4e615d9bcab4e3b84905b182e2ac8d106b0d25`, the PR62 squash merge. This bounded read-through covered queue-management dialogs/commands, draft validation, message export, rule editing and routing-provider plumbing. Confirmed fixes are confined to the RabbitMQ headers binding editor, rather than a claim that all reviewed paths are defect-free.

Three correctness problems were reproduced before changing product code:

- Loading a management-API binding with a null header argument and saving it changed null into the string `"null"`. The original binding received a message with that header present; the saved binding rejected it. The tests use `RabbitMqWorkspace.ToRule` on real-shaped management JSON, then the editor and routing matcher. Both an unchanged save and changing the MATCH selector reproduced the loss. RabbitMQ's [headers-exchange implementation](https://raw.githubusercontent.com/rabbitmq/rabbitmq-server/v4.1.0/deps/rabbit/src/rabbit_exchange_type_headers.erl) confirms that a void binding argument checks header presence. RabbitMQ editor values now treat unquoted `null` as a presence check; quoted `'null'` remains literal text. The dialog explains the distinction. The shared value parser used by other services is unchanged.
- Repeating a header name silently overwrote its earlier value, including names with surrounding whitespace. The dialog now rejects duplicates with an actionable error and stays open. Distinct case-sensitive names remain valid.
- A header-text line named `x-match` overwrote the MATCH dropdown, including an invalid numeric mode that would later be rejected by the broker. The reserved name is now rejected and the operator is directed to the selector.

Test-only commit `a9b55c2edf76d8888af1941f41eaeeafbec33532` preserves seven failing unit cases and two passing controls. The first UI invocation exposed a missing namespace import in the fixture; its compile log is retained. Test-only commit `bcf45786a44903496d4efb076e080ad35cbb4d9b` preserves the corrected fixture, re-proven red on unchanged product code: three failing real-modal-window tests. They exercise TextBox binding and the actual confirm-button event, verify that invalid input keeps the dialog open with a visible error, and inspect the rule returned from saving a presence condition. No assertion was suppressed.

After the minimal fix, all nine new unit cases pass; the focused unit run passes 15 cases including existing routing-review regressions. Five focused UI cases pass, including three new modal regressions and existing routing windows, with no binding errors. Full Windows validation with portable SDK 10.0.401 passes 1,123 unit tests and 77 UI tests, with zero skips in those suites. Locked restores and Release solution/Lab builds succeed with zero warnings/errors. The integration suite was invoked and reports 65 explicit skips because broker emulators are not configured locally; this is not a local live-broker validation. Exact-head cross-platform, emulator and package CI remains required before parent acceptance/merge.

Read-through checked the apparent destination-metadata loss in the editor against its caller: `TopicRoutingViewModel.ForDestination` restores the queue/exchange identity before saving, so that was not reported or changed. Fanout/plugin bindings are not editable through this path. Existing numeric/boolean conversion, unsupported-type errors, provider mutation logic and non-RabbitMQ rule parsing are covered by the unchanged full suite.
