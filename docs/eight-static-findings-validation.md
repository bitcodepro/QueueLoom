The retained test-only history begins at `20369988bf594815330627a0338acced79efc099`. Its [red CI run](https://github.com/bitcodepro/QueueLoom/actions/runs/37039993520) built successfully and failed the assertions on Windows, Linux and macOS; the isolated emulator job passed. Four actual routing-window UI cases separately failed after collecting dispatcher exceptions, so those failures did not terminate the runner. No live user brokers were contacted.

The 62 broker integration tests compile and are skipped locally because emulators are not configured; the existing CI runs them and broker UI scenarios in isolated containers. Release solution and Lab builds pass with zero warnings/errors. Repository restores use locked mode with vulnerability auditing enabled; sandbox-only NuGet audit connectivity failures are retained and resolved with authorized network access.

One full local run reported a pre-existing Windows updater test race: its fixed-delay read of `.queueloom-download` overlapped cleanup recreating that marker after a locked archive prevented directory deletion. The unchanged cleanup implementation and test are outside this fix. The failure log is retained; after diagnosis, the complete unit suite passed 958/958. No test assertion was removed or suppressed. An initial packaging invocation also retained its PowerShell argument-parsing failure; corrected arguments exposed that the repository's runtime-agnostic locks do not contain the self-contained RID/ILLink graph. Packaging validation therefore uses a separate disposable worktree, preserving repository lock files, and verifies that generated runtime graph in locked mode.
