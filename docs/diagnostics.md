# Local diagnostics

Choose **Settings → Export diagnostics**, or **Export diagnostics** beside an operation error or an updater failure. Review the `report.txt` and `diagnostics.json` tabs, then choose a new local ZIP filename. Cancel or close the preview to stop. Dismissing the save picker writes nothing. Existing files are never replaced, including after a save-picker overwrite confirmation. No report is uploaded, sent, or attached to GitHub.

The two files contain the same troubleshooting fields. The report captures an immutable view of the current application session: application assembly version, operating system/version/architectures, known operation kinds, broker type, recorded stages and UTC timestamps, known error categories/codes, and bounded application stack method metadata. Broker addresses and entity references become report-local placeholders. Local paths and all SDK/test/external stack frames are omitted. Placeholder numbers have no meaning across separate reports.

Updater events record checksum verification/mismatch at the actual comparison, installation completion, restart handoff, startup acknowledgement, and verified restoration when these happen in the reporting process. The detached update helper is a separate process; its history is not imported. Previous-session receipts and helper logs are not read. Missing facts stay unknown. A completed UI command may contain a cancelled confirmation or handled partial failure, so command completion alone does not confirm delivery. A successful direct composer send records provider acknowledgement; this does not assert consumer receipt. Only an explicit `DeliveryRejectedException` records a rejected operation.

The journal keeps at most 64 typed events in memory. Each error event includes at most four exceptions, traversed to nested causes, and three application stack methods per exception. Older events and excess details can be omitted. If necessary, older events are removed from the captured report until the combined UTF-8 files fit 256 KiB; counts identify retention/size omissions. This is a bounded troubleshooting summary, not a complete audit or an operation recovery source.

The exporter never reads logs, Activity prose, settings/configuration files, environment variables, credential vaults, snapshots, backups or command lines. It never collects message bodies or headers, connection strings, arbitrary exception messages, exception `Data`, custom exception type names or raw stacks. The collector maps known constants/enums; unknown/free-text inputs are omitted or replaced with a fixed category. It does not rely on regex redaction of unrestricted text. Operation-specific result details that are not explicitly instrumented remain unknown.

Review before sharing publicly: version, OS version, timing, broker type, error codes and application methods still reveal technical context. This feature minimizes collection; it does not promise secrecy for unrestricted free text in other application displays or files. The ZIP contains only the frozen preview, with fixed entry names and timestamps. Saving uses a unique temporary file in the selected directory, then a create-only move. Failure/cancellation cleans that owned staging file without replacing or deleting unrelated files.
