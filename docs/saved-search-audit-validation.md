# Saved search audit: identity, missing environments and empty selection

This is cycle 1 of the two requested audits after PR #60. Its baseline is current `main` at `7fbf390c3b435b16cec2ff8869f3499573740456`, the squash merge of PR #60. This is a bounded audit, not a claim that every repository path is defect-free. Read-through covered scheduled execution/persistence, message and environment export/import, body/schema decoding, Pub/Sub topology/send paths, settings normalization and saved-search execution. Confirmed fixes are confined to saved-search handling and its message-list UI.

Two user-visible correctness problems were reproduced before changing product code:

- Saving queries with the same first 40 characters replaced the earlier bookmark. Case-sensitive JSON queries such as `$.region == 'EU'` and `$.region == 'eu'` also replaced each other because identity used a case-insensitive display label. Identity now uses the full ordinal query, environment ID and time window. Colliding labels receive distinct suffixes so both bookmarks survive settings normalization and restart. Re-saving the exact query updates its bookmark.
- Choosing a bookmark whose saved environment has been deleted silently searched the currently selected environment. The bookmark now clears the scope/results, displays an actionable error and does not issue a search or connection request. Legacy bookmarks with a null environment ID retain their documented use of the currently selected environment.

The same real-window tests exposed a smaller existing binding defect when no message is selected: negating `SelectedMessage?.CanOpenAsDraft` attempts to convert null to a boolean. A separate test reproduced it on unchanged product code. A null-safe view-model boolean now controls the read-only preview warning and is notified when the selection changes.

Test-only commit `a012e0cc5ad1e58ed51566e527cb40a2c99bc230` retains the first reproductions: 3 failing unit cases with 2 passing controls, and 2 failing UI cases. The first UI invocation used a synthetic click event that did not execute the button command; that diagnostic log is retained. The corrected fixture invoked the real bound command and was re-proven red on unchanged product code (one saved item instead of two). No assertion was suppressed. Additional test-only commit `635d7e8690af95862fd0c532221d867ea885eb4d` retains the empty-selection binding reproduction, separately proven red with the product file restored to the baseline before testing and the pending fix preserved/restored afterward.

The regressions, including the review follow-ups below, are green: 15/15 unit cases and 4/4 headless UI cases, including settings round-trip, exact-query re-save, window identity, legacy unscoped search and no binding warnings. Full local validation passes 1087 unit tests and 69 headless UI tests, with zero skips in those suites. Release solution and Lab builds have zero warnings/errors. The integration suite was invoked and reports 65 explicitly skipped tests because no broker emulators are configured locally; this is not a successful broker validation. Cross-platform execution, emulator integration and package checks must be verified by the parent on the exact PR head in CI.

Logs and TRX are retained in `post-pr60-cycle1-20261003/evidence`, including failed diagnostic/initial green runs. Independent review reproduced two incomplete missing-environment cases on PR head `abdd7038f4bb0e804d410269b664ac2e90e013ca`: a delayed search restored old-environment results after selecting an unavailable bookmark, and selecting an unavailable bookmark with an already-null scope retained messages browsed through Explorer. Test-only commit `8ae525c4a19a05c6b619b3e26fc6f47dfb7bb1ef` retains four deterministic failing cases, covering repeated selection of the same or another bookmark and restoring the original scope before late completion. An unavailable bookmark now explicitly clears results, selection and browse paging, and invalidates the pending search generation. The search still performs its normal connection restoration, but cannot publish obsolete results afterward; a fresh legacy search remains functional. All nine saved-search unit cases and four real-window UI cases pass, including the Explorer/picker scenario. Follow-up logs and TRX are retained in `pr61-review-followup-20261003/evidence` on E:.

The subsequent browse review reproduced six failures on unchanged product head `ce65f9a3fc8ab15d383b45387f6e2e22ed9edd7b`, retained in test-only commit `159fa187c5cbe65356c0b5b6dde78606f65e114a`. A deterministic gate holds either the next page, first page or connection before browsing. Selecting two unavailable bookmarks clears the list; releasing the gate previously repopulated 100 old messages, with either a null scope or the original scope restored before completion. Search and browse now share the same message-result generation. The page loader checks it immediately after the provider finishes, before advancing sequence/Kafka positions, adding messages or selecting one. Initial browse also checks after connection and after page loading, preventing obsolete paging setup, title and navigation updates. Provider cleanup is still awaited and the workspace gate is released normally. Each regression verifies that a fresh browse subsequently loads 100 then 200 unique messages with continuation at sequence 101.

All application writes to the main message list and selection were inspected: search through the synchronous `ReplaceMessages` helper and the shared page loader are the asynchronous producers. Explorer, DLQ browsing and Kafka rereading all use that loader. Pending/deletion completion only removes listed messages and selects among survivors; connection invalidation and purge only clear the list. They cannot repopulate the cleared list. Full unit validation also passes the existing 1,100-message paging test, non-positional provider request-limit tests, Kafka continuation tests and shutdown tests that hold cancellation-resistant cleanup. Browse follow-up evidence uses the `browse-` prefix in the same E: evidence directory; prior logs and manifests are preserved.
