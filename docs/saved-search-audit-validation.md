# Saved search audit: identity, missing environments and empty selection

This is cycle 1 of the two requested audits after PR #60. Its baseline is current `main` at `7fbf390c3b435b16cec2ff8869f3499573740456`, the squash merge of PR #60. This is a bounded audit, not a claim that every repository path is defect-free. Read-through covered scheduled execution/persistence, message and environment export/import, body/schema decoding, Pub/Sub topology/send paths, settings normalization and saved-search execution. Confirmed fixes are confined to saved-search handling and its message-list UI.

Two user-visible correctness problems were reproduced before changing product code:

- Saving queries with the same first 40 characters replaced the earlier bookmark. Case-sensitive JSON queries such as `$.region == 'EU'` and `$.region == 'eu'` also replaced each other because identity used a case-insensitive display label. Identity now uses the full ordinal query, environment ID and time window. Colliding labels receive distinct suffixes so both bookmarks survive settings normalization and restart. Re-saving the exact query updates its bookmark.
- Choosing a bookmark whose saved environment has been deleted silently searched the currently selected environment. The bookmark now clears the scope/results, displays an actionable error and does not issue a search or connection request. Legacy bookmarks with a null environment ID retain their documented use of the currently selected environment.

The same real-window tests exposed a smaller existing binding defect when no message is selected: negating `SelectedMessage?.CanOpenAsDraft` attempts to convert null to a boolean. A separate test reproduced it on unchanged product code. A null-safe view-model boolean now controls the read-only preview warning and is notified when the selection changes.

Test-only commit `a012e0cc5ad1e58ed51566e527cb40a2c99bc230` retains the first reproductions: 3 failing unit cases with 2 passing controls, and 2 failing UI cases. The first UI invocation used a synthetic click event that did not execute the button command; that diagnostic log is retained. The corrected fixture invoked the real bound command and was re-proven red on unchanged product code (one saved item instead of two). No assertion was suppressed. Additional test-only commit `635d7e8690af95862fd0c532221d867ea885eb4d` retains the empty-selection binding reproduction, separately proven red with the product file restored to the baseline before testing and the pending fix preserved/restored afterward.

The same regressions are green: 5/5 unit cases and 3/3 headless UI cases, including settings round-trip, exact-query re-save, window identity, legacy unscoped search and no binding warnings. Full local validation passes 1077 unit tests and 68 headless UI tests, with zero skips in those suites. Release solution build has zero warnings/errors. The integration suite was invoked and reports 65 explicitly skipped tests because no broker emulators are configured locally; this is not a successful broker validation. Cross-platform execution, emulator integration and package checks must be verified by the parent on the exact PR head in CI.
